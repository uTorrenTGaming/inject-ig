## 1. Identidade Visual e Estética (A Regra de Ouro)
Nosso sistema **NÃO É** um painel comum de botões quadrados. O `inject-ig-admin` e o `inject-ig-console` seguem estritamente as métricas **Apple HIG (Human Interface Guidelines)**:
- **Janelas Nativas:** A janela nunca abre engolindo a tela. Tamanho inicial agradável (ex: 1050x700). Barra de título oculta (`titleBarStyle: 'hiddenInset'`), integrando os botões "Traffic Lights" do Mac (vermelho, amarelo, verde) ao layout através de um `padding-top: 45px` na barra lateral.
- **Vibrancy & Vidro:** Usamos o efeito de material Apple. Cores base são semi-transparentes (`rgba(...)`) com pesados `backdrop-filter: blur(25px a 40px)` no CSS e o equivalente no Electron (`vibrancy: 'sidebar'`, `backgroundColor: '#00000000'`).
- **Geometria Pílula (Pill Shape):** Botões possuem `border-radius: 6px`. Painéis e Cards possuem `border-radius: 12px`.
- **Prevenção de Vazamento Visual:** Nunca deixamos tabelas "vazarem" a tela. Usamos `table-layout: fixed`, definimos larguras com `%` ou `px` fixo, e o famoso `text-overflow: ellipsis; white-space: nowrap; overflow: hidden;` para que textos gigantes como o *Hardware ID* não empurrem e destruam o layout dos botões.

## 2. Compilação e Deploy (O Sistema Autônomo)
A engrenagem principal de atualizações para as máquinas "clientes" é sagrada e deve funcionar num fluxo invisível:
- **Script Mestre:** Usamos o `./publicar_atualizacao.sh` localizado na pasta `atualizacao/`.
- **Draft Bypass:** O `electron-builder` por padrão tenta lançar atualizações no GitHub como Rascunhos (Drafts). Para que ele jogue a atualização direto no ar para as vítimas baixarem no mesmo segundo, usamos um *hack* no script: `export EP_DRAFT="false"`.
- **Faxina do hdiutil:** O macOS sofre de um bug silencioso de "Discos de Imagem Fantasmas" (`hdiutil`) ao compilar o `.dmg`. Sempre rodamos um comando de desmontagem forçada e `rm -rf dist.nosync` antes de compilar o Mac, caso contrário, o arquivo `latest-mac.yml` dá erro de 404 e os computadores param de ser atualizados.
- **Espaço em Disco (ENOSPC):** O processo de empacotar Windows, Mac e Linux simultaneamente gera arquivos muito pesados na pasta invisível de caches. Se o processo der crash de "No Space Left", a regra é apagar os diretórios `~/Library/Caches/electron/*` para devolver até 5GB de fôlego à máquina.

## 3. Criptografia e Bloqueios do GitHub
O GitHub possui sistemas agressivos de bloqueio ("Push Protection") e leitores de código.
- **Nunca "Hardcodar" Tokens:** As senhas do banco de dados (Supabase) ou tokens da API do GitHub (`ghp_...`) não podem ser colados em texto puro dentro do código.
- **Estratégia de Ofuscação Passiva:** Quando precisarmos usar um token no código que o Electron vai empacotar, quebramos a string no meio ou usamos concatenação: `const parte1 = "sb_key..."; const final = parte1 + "resto";` para driblar os robôs do GitHub.
- **Reescrita de Histórico:** Se alguma senha vazar no GitHub, não adianta só apagar no arquivo. Foi necessário rodar um `git filter-branch --tree-filter 'sed ...' --force HEAD` para viajar no tempo do repositório, purgar o texto e usar `git push --force`.

## 4. Banco de Dados (Supabase)
Todo o controle do C2 flui pelo Supabase. O `.env` guarda a conexão local na pasta raiz, mas no ambiente de produção do painel Admin, ele consome via CDN ofuscado (quando necessário) ou variáveis injetadas.
Sempre respeitar o schema predefinido: Hardware ID, User, OS e a flag tática `is_banned`.
